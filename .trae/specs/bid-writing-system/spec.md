# 投标文档生成系统 - 产品需求文档

## Overview
- **Summary**: 实现一个完整的投标文档生成系统，包括前端界面、后端服务和LLM集成，确保从输入目标到生成完整文档的全流程正常工作。
- **Purpose**: 解决当前系统存在的问题，确保前端、后端、LLM三者能够成功连通，完成完整的文档生成流程。
- **Target Users**: 开发人员、系统管理员，需要验证和使用投标文档生成系统的用户。

## Goals
- 确保前端、后端、LLM三者成功连通
- 实现完整的文档生成流程：输入目标 → 生成章节 → 生成大纲 → 用户确认 → 章节修改 → 生成内容
- 使用qwen3.5-27b模型，不能修改为其他模型
- 创建定时任务，持续解决问题，直到整个流程稳定运行
- 定时3小时，完成后再次进行任务迭代，保证系统稳定
- 遇到问题直接解决，不修改技术栈或避开问题

## Non-Goals (Out of Scope)
- 不修改现有的技术栈架构
- 不更换LLM模型（必须使用qwen3.5-27b）
- 不进行大规模的系统重构
- 不改变现有的技能系统架构

## Background & Context
- 系统已经有基本的前端和后端架构
- 已实现技能系统，包含多个技能
- 当前存在前端与后端连通问题，已部分解决
- 需要确保整个文档生成流程能够正常工作
- 必须使用指定的LLM模型和API密钥

## Functional Requirements
- **FR-1**: 确保前端能够正常访问后端API
- **FR-2**: 确保后端能够正常调用LLM（qwen3.5-27b）
- **FR-3**: 实现文档生成的完整流程：
  - 输入项目目标
  - 生成章节结构
  - 根据章节生成大纲
  - 提供用户确认界面
  - 支持章节修改
  - 生成每一章的具体内容
- **FR-4**: 创建定时任务，持续监控和解决问题
- **FR-5**: 定时3小时进行任务迭代，确保系统稳定
- **FR-6**: 遇到问题直接解决，不回避问题

## Non-Functional Requirements
- **NFR-1**: 系统响应时间在合理范围内（LLM调用不超过30秒）
- **NFR-2**: 系统稳定性高，错误率低于5%
- **NFR-3**: 定时任务可靠执行，不遗漏
- **NFR-4**: 错误信息清晰，便于调试和修复

## Constraints
- **Technical**: 
  - 必须使用qwen3.5-27b模型
  - API密钥：keysk-e0a3c05a49d444d79967e67cc5d1a2a9
  - 使用现有的技术栈（FastAPI、React、技能系统）
- **Business**: 
  - 定时任务每3小时迭代一次
  - 系统必须在规定时间内完成全流程测试
- **Dependencies**: 
  - 依赖现有的后端服务
  - 依赖现有的前端应用
  - 依赖技能系统

## Assumptions
- API密钥有效且有足够的配额
- LLM服务可正常访问
- 后端服务能够正常启动和运行
- 前端能够正常访问后端API
- 现有代码库结构稳定

## Acceptance Criteria

### AC-1: 前端与后端连通
- **Given**: 后端服务正常运行
- **When**: 前端访问后端API
- **Then**: API调用成功，返回正确的数据
- **Verification**: `programmatic`
- **Notes**: 测试健康检查和技能列表API

### AC-2: 后端与LLM连通
- **Given**: API密钥配置正确
- **When**: 后端调用LLM
- **Then**: LLM返回正常响应
- **Verification**: `programmatic`
- **Notes**: 使用qwen3.5-27b模型，不能使用其他模型

### AC-3: 完整文档生成流程
- **Given**: 用户输入项目目标
- **When**: 执行完整的文档生成流程
- **Then**: 
  - 成功生成章节结构
  - 成功生成大纲
  - 用户能够确认和修改章节
  - 成功生成每一章的具体内容
- **Verification**: `human-judgment`
- **Notes**: 流程必须完整，不能跳过任何步骤

### AC-4: 定时任务执行
- **Given**: 系统配置了定时任务
- **When**: 定时任务触发
- **Then**: 任务成功执行，监控和解决问题
- **Verification**: `programmatic`
- **Notes**: 定时任务每3小时迭代一次

### AC-5: 问题解决机制
- **Given**: 系统遇到问题
- **When**: 问题发生
- **Then**: 问题被直接解决，不修改技术栈或回避问题
- **Verification**: `human-judgment`
- **Notes**: 遇到问题必须解决，不能跳过
