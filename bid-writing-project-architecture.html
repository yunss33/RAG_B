Docker First / RAG First / Human in the Loop

标书写作多智能体项目架构图

这套架构适合你现在的阶段：先在 Docker 环境里把“招标解析、RAG 检索、章节写作、审查、插图选择、HTML 成稿”跑通， 用编排器控制多智能体，而不是做成完全自由对话的 Agent 社会。核心原则是强流程、强证据、强可追踪、关键节点可人工确认。

接入层：前端与 API 编排层：任务状态机 + 多智能体调度 能力层：解析 / 写作 / 审查 / 插图 知识层：RAG、证据绑定、图片资产 存储层：Postgres / Redis / MinIO / Qdrant

一、Docker 服务分层

推荐先用 Docker Compose，不要一开始上 Kubernetes

frontend

Next.js / 管理台与预览端

  • 上传招标文件、知识资料、图片素材
  • 展示章节生成进度与 Agent 状态
  • 提供图片候选选择界面

api-gateway

FastAPI / 统一入口

  • 项目、任务、文件、权限接口
  • 触发编排任务与查询状态
  • 承接前端与内部服务协议

orchestrator

多智能体总控核心

  • 拆任务、建 DAG、控重试
  • 决定哪些 Agent 并行或串行
  • 维护项目级上下文与阶段状态

agent-runtime

统一执行各类 Agent

  • 招标解析、规划、写作、审查、插图
  • 统一 Prompt、工具调用、上下文装载
  • 输出标准化结果给编排器

二、知识与数据底座

不联网条件下，知识库就是系统的大脑

rag-service

检索、重排、证据回传

  • 文档切片、Embedding、召回、重排
  • 支持章节级 query 与评分点检索
  • 返回证据片段与来源元数据

qdrant

向量索引

  • 企业资料库
  • 历史标书库
  • 图片与附件元数据索引

minio

对象存储

  • PDF、DOCX、图片、扫描件
  • 中间稿与最终 HTML 成稿
  • 附件、封面、图表素材

postgres + redis

业务数据 + 队列缓存

  • 项目、任务、章节、引用、审查结果
  • 任务队列、缓存、锁与会话态
  • 人工确认节点状态

三、核心 Agent 分工

不要自由漫游，全部挂在编排器下面执行

招标解析 Agent

输入：招标文件

  • 抽取资格项、评分项、废标项
  • 生成结构化 requirement schema

策略规划 Agent

输入：requirements + 项目目标

  • 制定章节策略与写作优先级
  • 定义每章需要的证据类型

RAG / 证据 Agent

输入：章级 query

  • 召回证据、绑定来源、标记缺证
  • 把知识变成可引用材料

章节写作 Agent

输入：brief + evidence

  • 并行生成技术、商务、实施、售后章节
  • 输出草稿与待补资料项

合规审查 Agent

输入：草稿 + requirements

  • 检查漏响应、格式风险、废标风险
  • 输出整改意见

一致性校对 Agent

输入：全书草稿

  • 检查参数、项目名、时间、人员一致性
  • 发现前后冲突与重复

插图决策 Agent

输入：章节内容 + 图片库

  • 生成插图建议，不直接自动插图
  • 等待用户确认候选图

成稿装配 Agent

输入：终稿章节 + 图片选择

  • 合并目录、章节、图题、附录
  • 输出 HTML，后续扩展 DOCX/PDF

四、项目主流程

这条链路适合做成状态机，每一步都可追踪

1. 创建项目 上传招标文件、企业知识、历史案例、图片资产
2. 招标解析 提取 requirements、评分点、废标项、格式约束
3. 制定策略 定义章节结构、写作策略、证据需求
4. RAG 取证 按章节召回企业资料、案例、资质和图片候选
5. 并行写作 多章节并行起草，统一格式与语气
6. 多轮审查 合规、一致性、评分模拟反推修订
7. 图片选择 给用户候选图和插入位置，人工确认
8. 成稿装配 插图、编号、目录、附录统一输出
9. 导出交付 生成 HTML 成稿，并保留可追溯证据链

五、建议目录结构

适合单仓启动，后续再拆服务

  • apps/frontend：前端管理台与预览端
  • apps/api：网关接口与项目服务
  • apps/orchestrator：编排器、状态机、任务流
  • apps/agent-runtime：各类 Agent 执行器
  • apps/rag-service：文档导入、切片、检索、重排
  • packages/common：共享 schema、DTO、枚举、日志协议
  • packages/prompts：各 Agent Prompt 模板与策略
  • infra/docker：compose、nginx、初始化脚本

六、关键设计决策

先把方向定对，后面实现会轻很多

编排模式 用 Supervisor + 状态机，不用开放式 Agent 自由对话。
图片策略 图片必须经过“候选 -> 用户确认 -> 成稿装配”。
RAG 原则 所有关键结论尽量绑定证据来源，减少幻觉和夸大。
部署策略 先 Docker Compose 单机跑通，再考虑服务拆分和扩容。
