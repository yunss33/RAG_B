# DeepBS 使用指南

## 概述

本指南详细说明了如何使用 DeepBS 项目的功能，包括项目创建、文件上传、文档处理、标书生成等操作流程。

## 基本概念

### 项目

项目是 DeepBS 的核心概念，代表一个招标标书的创建过程。每个项目包含以下内容：
- 项目基本信息（名称、描述、目标语言）
- 源文件（招标书、知识库、案例等）
- 需求分析结果
- 大纲
- 草稿
- 评审问题
- 图片建议
- 最终HTML

### 源文件类型

- **tender**: 招标书文件
- **knowledge**: 知识库文件
- **case**: 案例文件
- **image**: 图片文件
- **other**: 其他文件

### 项目阶段

- **created**: 项目创建完成
- **ingesting**: 文件处理中
- **planning**: 规划中
- **drafting**: 草稿生成中
- **reviewing**: 评审中
- **waiting_user**: 等待用户输入
- **assembling**: 组装中
- **completed**: 完成
- **failed**: 失败

## 前端工作台使用

### 1. 访问前端工作台

启动服务后，通过以下地址访问前端工作台：
- Frontend: `http://localhost:3000`

### 2. 创建项目

1. 在首页点击「创建项目」按钮
2. 填写项目名称、描述和目标语言
3. 点击「创建」按钮

### 3. 上传文件

1. 进入项目详情页面
2. 点击「上传文件」按钮
3. 选择文件类型（tender、knowledge、case、image、other）
4. 选择要上传的文件
5. 点击「上传」按钮

### 4. 处理文件

1. 上传文件后，点击「处理文件」按钮
2. 系统会自动进行文档分块、向量生成等处理
3. 处理完成后，项目状态会更新

### 5. 运行项目

1. 文件处理完成后，点击「运行项目」按钮
2. 系统会自动进行需求分析、大纲生成、草稿撰写等操作
3. 运行过程中，项目状态会实时更新

### 6. 查看需求分析

1. 项目运行到规划阶段后，点击「需求」标签
2. 查看系统分析出的需求列表
3. 可以根据需要修改或补充需求

### 7. 查看大纲

1. 项目运行到规划阶段后，点击「大纲」标签
2. 查看系统生成的大纲
3. 可以根据需要调整大纲结构

### 8. 查看草稿

1. 项目运行到草稿阶段后，点击「草稿」标签
2. 查看系统生成的草稿内容
3. 可以根据需要修改草稿内容

### 9. 处理评审问题

1. 项目运行到评审阶段后，点击「草稿」标签
2. 查看系统生成的评审问题
3. 根据评审问题修改草稿内容

### 10. 选择图片

1. 项目运行到等待用户输入阶段后，点击「图片」标签
2. 查看系统生成的图片建议
3. 选择要使用的图片，设置放置位置和布局
4. 点击「提交选择」按钮

### 11. 查看最终HTML

1. 项目运行到完成阶段后，点击「最终」标签
2. 查看系统生成的最终HTML
3. 可以下载或分享最终HTML

## API 使用

除了前端工作台，还可以通过 API 接口使用 DeepBS 的功能。

### 1. 创建项目

```bash
curl -X POST http://localhost:8100/projects \
  -H "Content-Type: application/json" \
  -d '{"name": "Test Project", "description": "Test Description"}'
```

### 2. 上传文件

```bash
curl -X POST http://localhost:8100/projects/{project_id}/files \
  -F "file=@test.txt" \
  -F "file_type=tender"
```

### 3. 处理文件

```bash
curl -X POST http://localhost:8100/projects/{project_id}/ingest
```

### 4. 运行项目

```bash
curl -X POST http://localhost:8100/projects/{project_id}/run
```

### 5. 获取项目状态

```bash
curl http://localhost:8100/projects/{project_id}/status
```

### 6. 获取项目需求

```bash
curl http://localhost:8100/projects/{project_id}/requirements
```

### 7. 获取项目大纲

```bash
curl http://localhost:8100/projects/{project_id}/outline
```

### 8. 获取项目草稿

```bash
curl http://localhost:8100/projects/{project_id}/drafts
```

### 9. 获取图片建议

```bash
curl http://localhost:8100/projects/{project_id}/image-suggestions
```

### 10. 设置图片选择

```bash
curl -X POST http://localhost:8100/projects/{project_id}/image-selections \
  -H "Content-Type: application/json" \
  -d '[{"suggestion_id": "suggestion-id", "accepted": true, "placement": "top", "layout": "full"}]'
```

### 11. 获取最终HTML

```bash
curl http://localhost:8100/projects/{project_id}/final-html
```

## 最佳实践

### 1. 项目创建

- 项目名称应清晰明了，反映项目的内容和目标
- 项目描述应详细说明项目的背景、要求和期望结果
- 选择合适的目标语言，确保生成的标书符合语言要求

### 2. 文件上传

- 上传完整的招标书文件，确保系统能够全面了解招标要求
- 上传相关的知识库文件和案例文件，为系统提供更多参考信息
- 上传高质量的图片文件，提升最终标书的视觉效果

### 3. 需求分析

- 仔细审查系统生成的需求列表，确保所有重要需求都被识别
- 根据实际情况，添加或修改需求，确保需求分析的准确性
- 特别关注强制性需求和高风险需求

### 4. 大纲调整

- 根据招标要求和项目特点，调整大纲结构
- 确保大纲覆盖所有重要内容，逻辑清晰
- 合理安排章节顺序，提高标书的可读性

### 5. 草稿修改

- 仔细审查系统生成的草稿内容，确保内容准确、完整
- 根据评审问题，及时修改草稿，提高标书质量
- 注意语言表达和格式规范，确保标书符合要求

### 6. 图片选择

- 选择与内容相关的图片，增强标书的可视化效果
- 合理设置图片放置位置和布局，提高标书的美观度
- 确保图片质量清晰，分辨率适当

### 7. 最终检查

- 仔细检查最终HTML，确保所有内容正确无误
- 检查格式、布局和样式，确保标书美观专业
- 确认所有需求都已满足，所有问题都已解决

## 常见问题

### 1. 项目创建失败

- 检查网络连接是否正常
- 检查前端工作台是否可以正常访问
- 检查API服务是否正常运行

### 2. 文件上传失败

- 检查文件大小是否超过限制
- 检查文件格式是否支持
- 检查网络连接是否正常

### 3. 文档处理失败

- 检查文件内容是否完整
- 检查RAG服务是否正常运行
- 检查LLM配置是否正确

### 4. 项目运行失败

- 检查项目配置是否正确
- 检查依赖服务是否正常运行
- 查看服务日志，了解具体错误信息

### 5. 图片建议不相关

- 上传更多相关的图片文件
- 检查招标书内容，确保系统能够理解图片需求
- 手动选择合适的图片

### 6. 最终HTML质量不高

- 确保上传了高质量的源文件
- 仔细修改草稿内容，提高标书质量
- 合理选择和布局图片

DeepBS 项目提供了一个完整的招标标书生成流程，从项目创建、文件上传、文档处理到最终HTML生成。通过前端工作台或API接口，用户可以方便地使用这些功能，提高招标标书的生成效率和质量。
